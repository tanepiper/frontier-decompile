# Deviations from the original

Generated by `deviations.py` from comments in the sources: edit the comments, not this
file. Each entry is a place where the reimplementation differs from the original on

## `apps/game/src/main.rs`

- [Deviation] [line 1](../apps/game/src/main.rs#L1): `frontier`: Frontier: Elite II, native and in the browser. The game currently runs on the reference runtime (`frontier-dos`): the user's own `FRONTIER.EXE` and overlays execute on the in-process 386 interpreter, and this app supplies the window, the 320×200 frame, keyboard, mouse and timing. Native ports replace original routines as they are traced (docs/RUNTIME.md). Legacy DOS set-up is skipped (DEVIATIONS.md).

## `apps/game/src/render.rs`

- [Deviation] [line 1](../apps/game/src/render.rs#L1): Presents the game's 320×200 frame. The frame is produced in software exactly as the original writes it to `A000:0000` (palette indices through the VGA DAC), uploaded as an RGBA texture and scaled with nearest filtering into the largest 4:3 rectangle that fits the window. Deviation (DEVIATIONS.md): VGA scan-out is replaced by a GPU blit; pixels are unchanged.

## `apps/viewer/src/scene.rs`

- [Deviation] [line 1](../apps/viewer/src/scene.rs#L1): A model and its sub-objects as one list of shapes in the model's space, and drawing it. Deviation: this is the viewer's picture of the geometry, with its own orthographic camera, lighting and depth sort. The game's renderer (`1000:b207` and EL2MCGA3) is not used: sub-objects keep the parent's orientation; discs and thruster flames get a fixed screen size; textures are stretched over the whole face (the game picks one of 8 orientations, VIDEO.md §5.3), on a base grey from the viewer's light (the game's base is the face's shade word). By default the near branches are drawn with every model variable 0 (*assumed*), back faces are hidden by their stored normals as `face_shade` does, and textures are on; each can be turned off.

## `apps/viewer/src/sound.rs`

- [Deviation] [line 1](../apps/viewer/src/sound.rs#L1): Sound in the viewer, on the shared audio output (`frontier-platform`). - The AdLib music and effects are played by the original driver's port (`frontier_game::adlib`) running alone on the user's `EL2ADLIB.OVL` image, ticked at the game's 202.27 Hz into the OPL2 model: the same notes the game plays. - The `.ROL` MIDI songs were written for a Roland MT-32 (`EL2ROL`, docs/AUDIO.md §4). - [Deviation] [line 179](../apps/viewer/src/sound.rs#L179): MIDI on the OPL2: nine voices, one organ-like two-operator patch, notes allocated to the oldest free voice. Deviation: see the module comment.

## `crates/game/src/system.rs`

- [Not ported] [line 2127](../crates/game/src/system.rs#L2127): `EL2M00:3f20` (module 0, handler `+20`), *observed*: build a star system, or (with `DS:07c4` ≠ 0) make a body into a flight object, which is not ported (the port declines). In: `DX:AX` and `CX:BX` the system seed (`s0`, `s1`), `DS:07c8` (low byte) the number of stars, `DS:07d4` the system id, `[DS:07dc]` the record block, `[DS:07e4]` the system name, `DS:07d8` (low byte) the parent value. The counters are cleared, then: - `s0` high word 0: a hand-made system, looked up by id in `EL2M00:3ed9` (6-byte entries, id and record pointer; default `EL2M00:3a51`), its 40h-byte records copied with masses and radii made into floats (entries with `+0Ah` = 46h copied raw), names included; - one star: set up with `468a`, then the orbit builder; - two or more: a binary through `50d6` (mass `s1`), orbit spacing from the seed, the orbit builder with the mass scale `s1 + 081B_3200h` (FFFF_FFFFh beyond two); - 1 (or negative): one binary at an eighth of the mass scale. The record after the last body is zeroed (generated systems) or gets the end marker and `DS:202f`/`204d` from the table (hand-made ones).
- [Not ported] [line 2155](../crates/game/src/system.rs#L2155): The flight-object path (EL2M00:4275) is not ported.
